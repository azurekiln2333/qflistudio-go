# Integrate standalone products and prove the complete request

## Goal

Own parent R3/R6 and cross-product R1–R10 acceptance coordination, without competing with live product coordinators. Changes to shared files require declared per-file ownership and one integrator for aggregate content.

## Requirements and acceptance

- Confirm a shared owner for language chips/circles, highlighting, persistent multi-root explorer, diagnostic underlines and panels before editing those paths. Product coordinators own their real adapters/content.
- All supported languages have actual highlight tokens and correct extension aliases. Multi-language filters compose with search/level selection, and title badges match project labels.
- Sidebar recreation restores state. Persisted workspaces display multiple roots and preserve owning project identity for open files, run actions and diagnostics.
- Collect complete fresh per-product inventories, exact packaged runtime/content hashes and all-item OHOS execution reports, including C/C++ user headers and Python offline modules/package management.
- Run all affected shared/product analyses/tests and package/runtime inspection. Audit every parent requirement using actual evidence rather than passing narrow checks.
- Publish only audited task-owned changes with conventional commits and normal pushes; verify remote SHA or record exact failure. Preserve unrelated dirty work and app data.

## Dependencies and exclusions

Go curriculum child supplies Go all-item proof; Go IDE child supplies adapter/native/debugger proof. Other products supply their own current reports. Shared ownership is coordinated through global `qfli-core-release-sync`. No implementation in another product repository without the owner's agreement, no blind aggregate overwrite, no online app feature and no completion claim based only on Go.

# Go 教程体系课程目录（120 主题规划）

> 本文件是规划阶段产物，仅定义课程目录与每篇教程的统一实质内容要求。
> 不包含产品代码，不定义具体实现，实施阶段由主力 Pi 按此目录逐篇落地。
>
> 运行环境:桌面端使用官方 Go（go1.21+，含泛型）。移动端（OHOS/HarmonyOS）使用 Yaegi 解释器。
> 平台的特性支持差异必须在平台标记中注明。默认假设：仅标准库、离线、自包含、确定性输出。
> 每篇教程必须包含完整可运行程序，或与之等价的测试/小项目，而非仅摘录片段。
>
> **重要约束（与当前项目真实导入能力对齐）**：应用内 `CodeSnippet`/`CodeImportService` **只能导入单个代码文件**（一个 lesson/example 只有一段 `code` 字符串，导入时只写一个文件名，默认 `main.go`，入口为单个文件）。因此**不允许声称多文件工程、测试文件、模块目录可被自动导入**。目录中每个主题都明确标注交付形态（见「三、交付形态」）：可直接导入运行的 **main 演示**，或需要读者按教程手动搭建文件/运行官方 SDK 命令的 **工程例子**。

## 二、平台标记约定

- **Go**：官方 Go 工具链（桌面/服务器）。
- **Yaegi**：移动端解释器已确证可运行（仅有基础能力时使用，实施阶段需复测）。
- **Yaegi\*（待实测）**：移动端解释器下是否可运行尚需实测，**实施任务中验证**；不得预先承诺可运行。
- **Go only**：仅官方 Go；移动端本轮不支持，不得声称全平台可用。

> **泛型相关主题一律先标 `Go only`**（T062–T065 以及任何使用类型参数的主题），不得标注为 Yaegi 可运行。
> 泛型、`//go:embed`、`//go:generate`、`go test` 的全部子模式（bench/fuzz/race/cover）、`unsafe`、CGO、`net` 监听等在 Yaegi 下支持不完全。凡涉及这些特性，先标 `Go only` 或 `Yaegi\*（待实测）`，禁止默认宣称移动端可运行。
> 各标记是否成立，均由实施阶段的实测任务回填结论，规划阶段不做产品承诺。

## 三、交付形态（与真实导入能力对齐）

**当前项目事实（来自 `test/content_code_import_test.dart` 与 `CodeImportService`）**：
- 一个 lesson/example 仅携带一段 `code` 字符串；导入时只接受**一个文件名**，以**单文件**写入项目的 `src/` 目录。
- `CodeImportService.suggestedFileName('go') == 'main.go'`；`RunnerService.findEntry` 指向该单一入口文件。
- 不支持：多文件自动导入、测试文件自动导入、`go.mod`/模块目录导入、bench/fuzz/embed 资源导入。

因此每篇主题只按以下两种形态交付，目录中逐条标注：

- **`导入`（main 演示）**：单个自包含 `.go` 文件，`package main` + `func main()`，仅用标准库，确定性 stdout。可直接经 CodeSnippet 导入并运行。凡涉及多文件/测试的机制，一律降级为「在单个 main 文件中演示同一机制」。
- **`手搭`（工程例子）**：需要多个文件、测试文件、`go.mod`、目录结构或官方 SDK 命令（`go test`/`go test -bench`/`-fuzz`/`-race`/`-coverprofile`、`go generate`、`//go:embed` 资源）的例子。教程必须**手把手给出文件清单、每个文件内容与运行命令**，明确说明**不能**由 CodeSnippet 一键导入，由读者手动搭建。

> 规则：**任何标 `手搭` 的主题都必须在教程内声明「此例不能自动导入，需手动创建文件/运行官方命令」**。标 `导入` 的主题不得依赖任何第二文件。

## 四、每篇教程统一实质内容要求（所有 T001–T120 强制）

每篇教程必须包含以下 7 个部分，缺一不可，且不得以「标题 + 摘要 + 一段代码」的最低量交付：

1. **前置知识**：明确列出本篇依赖的先前主题 ID 与概念。
2. **概念讲解**：该主题的核心概念、为什么存在、与其他方案的取舍。
3. **逐段解释**：对示例代码按段落（不是按行堆砌）解释「这段在做什么/为什么这么写」。
4. **运行结果**：给出实际运行的确定性输出或测试结果，并与讲解对应。
5. **常见陷阱**：至少 2 条真实易错点（语义误区、边界条件、并发/内存/平台差异等）。
6. **练习**：至少 1 道可验证的动手练习，附判定标准（不给出完整答案）。
7. **完整示例**：一个可 `go run` / `go test` 的完整程序或小项目，独立目录、自包含。

按两种交付形态使用对应目录结构：

**`导入`（单文件 main 演示，可被 CodeSnippet 导入）：**
```
topic-TXXX-slug/
  main.go            # 单文件，package main，确定性 stdout
  README.md          # 上述 7 部分
  golden/            # 可选：固定期望输出
```

**`手搭`（工程例子，不能自动导入，需手动创建文件/运行官方命令）：**
```
topic-TXXX-slug/
  README.md          # 7 部分 + 明确的文件清单与运行命令
  go.mod             # 需要时（本地模块，无第三方依赖）
  main.go            # 或多个 .go 文件（教程手搭）
  xxx_test.go        # 测试类主题（教程手搭）
  golden/            # 可选
```

> 标 `手搭` 的教程必须在 README 顶部声明：「本例为工程例子，**不能**由 CodeSnippet 一键导入；请按下列文件清单手动创建，并运行官方 Go SDK 命令（如 `go test -bench`）。」

## 七、去重与质量约束（实施阶段验收依据）

1. **唯一性**：120 篇的主题、示例行为与验证方式两两不同；不得以「同一代码换标题/换数字」充数。
2. **示例真实**：每篇示例必须运行该主题的核心机制，而非仅在别处逻辑上换个常量。
3. **确定性（硬约束）**：
   - 示例严禁依赖易变值：**时间戳、墙上时钟、goroutine 完成/打印顺序、随机数、map 遍历顺序、主机名/路径**。
   - 并发/定时主题必须用「语义断言」消除非确定性：结果先**收集后排序再比较**，或断言**计数/集合相等/通道收到的值集合**，或断言「最终值 == 确定值」。不得直接比对时间或行序。
   - 时间主题（T092、T093）使用**固定时区 + 固定布局**，只断言解析/格式化结果，不断言当前时间；定时器只断言**触发次数上限**，不比对实际耗时。
   - 基准/性能主题（T036、T080、T108、T114）只输出 ns/op、allocs/op 供人阅读，**不得把具体数值作为通过条件**；硬性验证用功能等价断言（如输出正确性、分配次数上界）。
   - 哈希/校验（T098）对照**公开已知测试向量**，非运行时生成的随机输入。
4. **自包含与离线（硬约束）**：仅用标准库；需要网络的示例（T099–T104）一律用 `net/http/httptest` 或环回地址，不依赖任何外部服务或下载。

6. **导入契约诚实（硬约束）**：每个主题必须标注交付形态。标 `导入` 者必须是单文件 main、可作为单段 `code` 被 CodeSnippet 导入；标 `手搭` 者必须在教程内**明确声明不能自动导入**，并给出完整文件清单与运行命令。禁止任何「多文件/测试/模块可一键导入」的表述。
7. **统一结构**：全部采用第四节的 7 部分内容要求，并按交付形态使用对应目录结构。

## 八、导入契约与交付形态映射（与项目真实能力对齐）

**已核实的真实能力**（`qfli_studio_core/lib/services/code_import_service.dart`、`lib/widgets/code_snippet.dart`）：
- 一个 lesson/example 只携带**一段 `code` 字符串**；导入只接受**一个文件名**，写入单文件。

## 九、移动端（Yaegi）注意事项

- Yaegi 对泛型、`//go:embed`、`//go:generate`、`go test -race/-bench/-fuzz`、部分 `reflect`/`context`/`net` 能力支持不完整或有版本差异。
- **泛型相关主题（T062–T065）一律先标 `Go only`**，不得标注 Yaegi 可运行；其余涉及上述能力者标 `Go only` 或 `Yaegi\*（待实测）`。
- 移动端可优先使用的确定性主题：控制流、集合、字符串处理、基础错误处理、部分标准库（strings/strconv/sort/fmt/encoding/json）等。
- 上述标记的最终成立与否，由**实施阶段的实测任务**回填，规划阶段不做产品承诺。
